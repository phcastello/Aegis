## Transport endpoint and security boundary

`GET /api/nodes/connect`, WebSocket upgrade only. Production URL: **`wss://aegis.phcastello.com/api/nodes/connect`**. A normal authenticated HTTP request gets `400 websocket_required`. Query strings are rejected; credentials never appear in URLs. Handshake headers:

```http
Authorization: AegisNode <existing Stage 03 credential>
X-Aegis-Node-Protocol: 1
```

The existing ASP.NET `AegisNode` scheme and `NodeManagement` policy authenticate the upgrade. No second cryptographic validator. Invalid credentials are rejected with `401 node_authentication_required`, revoked identities with `401 node_revoked`, disabled Nodes with `403 node_disabled`. Wrong handshake protocol is `409 protocol_mismatch`. The technical `X-Aegis-Node-Error` header repeats the defined error code so the native client need not depend on reading a potentially fragmented HTTP error body. Unrecognized proxy errors are transient; raw server prose never becomes a public transport error.

Rust derives the WebSocket URL from the existing normalized, origin-bound API configuration. Official release builds require HTTPS/WSS; there is no downgrade or redirect fallback. Debug builds explicitly configured with HTTP may use WS for local/LAN fixtures. Do not use development plaintext with real production identities.

The native manager retrieves only a confirmed, non-revoked credential from the existing OS vault under the same native identity mutex. Pending establishment is resumed first. Unpaired/missing/revoked identities open no socket. Vue gets only `TransportStatus { transportState, lastError }` through narrowly scoped local Android/Windows IPC. It can request reconnect, but cannot read credentials, set the WebSocket destination or supply arbitrary transport frames. Header values are marked sensitive and library/request errors are not logged or returned. Existing identity, Keystore mapping, `com.aegis.node`, Android signing and updater signing contracts remain unchanged.

## Protocol v1

UTF-8 text JSON only; deterministic envelope fields `protocolVersion`, `type`, `messageId` (nonempty UUID), `sentAt` (RFC3339/ISO timestamp), optional `payload`. Client time is diagnostic only. Server timestamps determine presence and all stored transport history.

```json
{
  "protocolVersion": 1,
  "type": "hello",
  "messageId": "740f0405-4334-4a0f-b714-40a950be5bf7",
  "sentAt": "2026-10-03T15:00:00Z",
  "payload": { "appVersion": "0.7.0-stage.5" }
}
```

The server replies with `hello_ack`, the same messageId, its timestamp, and `payload: { heartbeatSeconds: 25, timeoutSeconds: 75 }`. Only after valid hello and a fresh administrative-state check is the session accepted by the client as Online. The backend registers a lease before that recheck: a concurrent disable/revoke either cancels the new lease after commit or is seen by the recheck. The application version updates the existing Node record; no new pairing/Node is created.

```json
{
  "protocolVersion": 1,
  "type": "heartbeat",
  "messageId": "9b2c5e53-9021-47c6-afab-83dfbc83060c",
  "sentAt": "2026-10-03T15:00:25Z"
}
```

The server sends `heartbeat_ack` with the same ID and its authoritative timestamp (`payload: null`). No command, capability, action, notification or location envelope exists.

Limits: 4096 bytes per assembled JSON message, hence also a bound on accepted frame/payload data; at most 32 receive fragments, JSON depth 8, exact top-level keys without duplicates, exact hello appVersion payload (80 chars maximum and existing version validation), no heartbeat payload. Binary, malformed JSON, unknown type, repeated hello, heartbeat before hello and incompatible versions close explicitly. A second heartbeat within five seconds closes for abuse. No compression negotiation. Pending upgraded sockets are capped at twice MaxConnections; registered Nodes default to 256. A lease is not Online until the fresh administrative check activates it. Global handshake admission is capped at 200 attempts/minute **before credential database validation**, with a further 60/minute socket-peer policy. Registry capacity rejection does not create presence. Behind a proxy, peer quotas may be shared; untrusted forwarded IP headers do not bypass them.

Close codes: `4000 replaced`, `4001 node_revoked`, `4003 node_disabled`, `4006 protocol_mismatch`, `4008 heartbeat_timeout`; normal shutdown `1000`/`1001`, oversized messages `1009`, other policy failures `1008`. Administrative closure removes presence immediately and sends a close reason before history flush. Normal connection errors preserve identity.

## Timing, registry and persistence

Defaults, configurable via `NodeTransport` configuration/environment keys such as `NodeTransport__HeartbeatSeconds`:

| Setting | Default | Meaning |
|---|---:|---|
| HeartbeatSeconds | 25 | Native application heartbeat interval negotiated in hello_ack |
| TimeoutSeconds | 75 | Maximum silence since hello/valid heartbeat |
| HelloTimeoutSeconds | 10 | Bound on the first application message |
| WatchdogSeconds | 5 | Registry stale-connection sweep |
| MinimumHeartbeatSeconds | 5 | Abuse protection |
| PersistSeconds | 120 | Throttled history flush during an active session |
| MaxConnections | 256 | Registered logical Node connections |

Invalid configuration fails startup. Backend timers use `TimeProvider`; tests advance a fake server clock to exercise expiry without minute-long sleeps. Lookup/availability checks reject expired leases immediately, even between watchdog sweeps; the watchdog also removes/cancels stale sockets. Deadline equality counts as expired.

`NodeConnectionRegistry` is a singleton keyed by NodeId. A new valid session replaces the previous lease with a unique ConnectionId and cancels it. Unregister is conditional on the exact lease object; old A cleanup cannot remove B. Public DTOs derive `availability: online/offline` from a fresh current lease AND administrative permission. Disabled/Revoked remain separate dimensions and always show Offline. `Connecting/Reconnecting` are native local states only. No PostgreSQL Online column exists. Backend restart starts with an empty registry: all Nodes Offline until reconnect.

Migration `20261003143744_AddNodeTransportHistory` adds only nullable historical `LastSeenAt` and `LastHeartbeatAt`. `LastSeenAt` is the backend time of the last valid authenticated **transport hello or heartbeat**; management-only HTTP calls do not imply reachability. `LastHeartbeatAt` is the backend receipt time of the last valid application heartbeat. Neither uses client `sentAt`. No LastConnected/LastDisconnected columns were added without a concrete need.

Presence/heartbeat stay in memory. Hello persists version/LastSeen; history flush occurs no more than once per two minutes during the session, then once at termination using the last actual interaction time, not disconnect time. SQL updates only these columns and uses monotonic timestamp predicates, preventing old cleanup from moving dates backwards or overwriting Enabled/Revoked. At a hard process crash durable history may lag up to the flush interval; Online still correctly becomes Offline immediately on restart. Persistence failures end the session and retain a technical log; the next connection can retry.

The registry is **process-local**, supported by the current single API instance. Multi-instance deployment needs shared presence/routing/pubsub design in a later stage. No Redis or cluster work is included here.

## Native reconnect and lifecycle

One manager/task owns one socket. Duplicate start is a no-op. Start/stop coordination prevents a second loop while shutdown awaits the previous task. Cancellation closes an active socket; Drop aborts unfinished work; reconnect drops the previous session before opening another. No credential is cached in public state or errors.

Transient failure: exponential delays `1, 2, 4, 8, 16, 30` seconds, jitter ±20%, hard maximum 30 seconds. Backoff resets after **120 seconds actually Online**; time spent attempting a failed handshake does not count. Socket connect/hello/write operations have ten-second bounds. Missing heartbeat acknowledgements also terminate the native session within the negotiated timeout and reconnect. Foreground/focus/visibility and manual Retry can wake the loop promptly; UI polling reads state only and does not spawn transports.

Disable: backend commits Enabled=false, removes/cancels the active lease and closes with 4003. The native client retains identity and waits **30–36 seconds** between disabled attempts; re-enable permits a later handshake automatically. Foreground or explicit Retry can retry sooner. Revoke: credential revoked, connection removed/closed with 4001, native vault replaced by the same secret-free tombstone as Stage 03; the loop terminates. Tombstone-write failure still stops the old retry loop and reports a safe storage error. Protocol mismatch terminates retries and shows “Esta versão da Aegis não é compatível com o servidor. Atualize o aplicativo.” A new pairing can start a fresh loop. Rejection is conditional on the credential actually used by that session: an old socket close cannot erase a newer pairing, and the sole loop continues with a replacement checkpoint rather than leaving it without transport.

Windows: active while the app process runs; normal full close stops transport, abnormal exit/network disappearance goes Offline by timeout. No tray/autostart/background resident process.

Android foreground: the same Rust transport is compiled into the Android native runtime. Native Resume/Focus and WebView visibility recovery request reconnect. Android background suspension may kill/freeze the socket, causing Offline; this is expected. Returning foreground reconnects. **No BackgroundReachable, FCM, foreground service, WorkManager, persistent background socket or attempt to defeat Android lifecycle.** Build/CI cannot establish physical background/foreground correctness.

UI additions are functional only: administrative status, Online/Offline, historical last-seen, and local Connecting/Online/Reconnecting/Offline/error text. The Nodes panel refreshes while open every ten seconds. Chat/HTTP/SSE, Gmail, Calendar, TTS, STT and Memory retain their existing transports.
