# Aegis v0.7.0 — It's Not Stalking. It's a Feature.

*You're terrible at hiding.*

Aegis reaches beyond an open conversation: native apps, paired devices, reminders
and places let her respond when something is due and when an arrival or departure
matters. You choose the devices, permissions and places involved.

## Highlights

- Native Aegis Nodes for **Android ARM64** and **Windows x86_64**, alongside the
  existing Web Client/PWA and shared chat, voice, history, memory and integrations.
- Persistent device identities, authenticated pairing and reconnection, native
  capabilities and selection of eligible destinations.
- Native notifications, recurring reminders, global **OK** and **Snooze**, and
  recovery of pending actions after interrupted connections.
- Places, contextual aliases and Android hybrid arrival/departure detection with
  an explicit distinction between the real area and its monitoring proximity.
- Revised settings, device/reminder/place editors, diagnostics and signed updates.

## Native Aegis Nodes

Each paired installation has a persistent identity, name, priority and supported
capabilities. Pairing codes connect devices without copying permanent credentials
between them. Settings lets you manage, disable or revoke devices. Normal restarts
and updates preserve the installation's identity and native credential storage.

Authenticated transport, availability and capabilities help Aegis choose a suitable
device for supported actions. Windows can remain available in the tray; Android
can receive background notifications through Firebase Cloud Messaging. A live
connection or push token does not prove that a device is awake or a message was seen.

## Notifications & Reminders

Personal reminders target all eligible devices by default; a single-destination
option keeps priority-based selection. Delivery results are tracked per recipient.
Daily, weekly and monthly series use local time and a time zone. Pause, resume,
skip and individual occurrence edits preserve the series without replaying a
backlog of expired reminders.

**OK** acknowledges the current occurrence. **Snooze** changes that occurrence's
next presentation while preserving the series schedule. Supported clients withdraw
other copies as they synchronize. Tapping the notification body opens the occurrence
without silently acknowledging it.

Offline actions remain pending locally and reconcile after a usable connection
returns. A snooze time requires server confirmation; older clients without copy
withdrawal may keep a notification that must be dismissed manually.

## Places & Geofencing

The map editor supports fixed places, rooms, contextual aliases and several circles
whose union defines the real area. Overlaps do not count as departures; gaps remain
outside. You explicitly select the phone supplying your personal location. A desktop
or remote desktop does not move your personal location to that computer; rooms
describe fixed context rather than indoor GPS detection.

Android hybrid geofencing combines native region events with bounded location
verification. A separately approved proximity area can start an approach check;
it neither enlarges the real place nor counts as arrival by itself. Verification
ends on success, cancellation or its limit of four and a half minutes and nine
location requests. Departure uses the real area. This is event-based detection
with temporary acquisitions, not continuous GPS or a real-time movement trail.

A rule distinguishes **saved** from **active on the phone**. A synchronized rule
can notify locally while the Aegis backend is unavailable and reconcile later.
Creating, restoring or updating a rule does not count as crossing a boundary.

The owner approved one physical route on **preview `.19` with battery saver on**:
departure from college delivered two reminders about a block later; passing near
home and approaching/circulating near the door produced no premature arrival;
actual entry was followed by two arrival notifications. This supports acceptance
of that route, without establishing universal accuracy or latency.

## Reliability & Updates

Settings brings together Nodes, Places, Reminders and Updates, with clearer errors,
pending synchronization and location diagnostics. Durable queues and duplicate
handling support interrupted connections and process recovery. Idle work has been
reduced; temporary location verification stops instead of becoming a permanent
GPS service. Earlier automated measurements remain attributed to their preview
builds in the technical record.

The shared Markdown renderer is updated to `markdown-it 14.3.3`, addressing a
[denial-of-service issue in malformed link reference parsing](https://github.com/markdown-it/markdown-it/security/advisories/GHSA-gfr2-rv44-r23c)
that could stall the chat interface.

Updates include manual checks, progress and visible network failures. Android
verifies package, version and signing identity before requesting system installation.
Windows uses the existing signed updater and an explicit install/restart step.
The historical `node-preview/latest.json` endpoint remains compatible with existing
installations and points to immutable stable downloads.

## Upgrading

Get the installers from the [native distribution](https://github.com/phcastello/Aegis/releases/tag/node-v0.7.0):

- [Android ARM64 APK](https://github.com/phcastello/Aegis/releases/download/node-v0.7.0/Aegis-Android-arm64.apk):
  version `0.7.0`, Android `versionCode 7000999`.
- [Windows x86_64 NSIS installer](https://github.com/phcastello/Aegis/releases/download/node-v0.7.0/Aegis-Windows-x86_64-Setup.exe).

**Install over the existing application; do not uninstall to update.** Preview
`.19` recognizes `0.7.0` as newer. The normal path preserves application identity,
Node pairing, credentials and local data. Android retains its existing application
ID and signing certificate; Windows retains its existing updater key and vault.
Installations still on `stage.10` need one manual installation of the current official
APK over the existing app because that old updater only recognizes `stage.N`.

Android APKs are distributed outside the Play Store. Geofencing requires Google
Play Services, active location services and precise/background location permission;
notifications require their applicable permission. Denying location leaves chat and
time-based reminders available. Linux, macOS and iOS apps are not distributed.

## Known Limitations

Android and manufacturers can delay callbacks, deny location requests and restrict
background execution. Small areas or poor accuracy can leave presence uncertain.
Force Stop, disabled location or missing service dependencies can prevent detection.
No instant arrival, universal residential accuracy or perfect GPS availability is
promised. A proximity session does not restart simply because the phone remains
nearby. Offline rules have renewable validity of up to seven days; remote revocation
requires synchronization or local expiry.

A Windows microphone capture problem was reported on one computer. No verified fix
was found for this release; an encoded silent recording can still reach STT. Physical
voice capture on that setup remains unverified. Windows installers do not have a
commercial publisher certificate, so SmartScreen may show an unknown publisher;
the updater signature is a separate verification mechanism.

The approved `.19` route does not establish every physical cancellation, offline
OK/Snooze, manufacturer, update or long-term battery scenario. See the
[completion record](https://github.com/phcastello/Aegis/blob/v0.7.0/docs/v0.7.0-completion.md)
and [release verification](https://github.com/phcastello/Aegis/releases/download/v0.7.0/RELEASE-VERIFICATION.md)
for evidence, signing identities, SHA-256 hashes and the scope of upgrade checks.
