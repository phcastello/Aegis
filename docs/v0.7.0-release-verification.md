commit, resolved tags, workflow run URLs, downloaded asset hashes and public feed

## Versions and distribution contracts

`apps/aegis-node/scripts/version.mjs` synchronizes Node, Rust, Tauri, shared client,
PWA and their lockfiles, including linked-package version records. Stable Android
`versionCode 7000999` is greater than `.19`'s `7000019`; SemVer likewise orders
`0.7.0` after `0.7.0-unstable.19`.

The Android package remains `com.aegis.node`, ARM64, with certificate SHA-256
`df5286c556657ddcee6ce79c510b967678bac8ced18d082db0e318bc47debb31`.
Distribution checks verify the packaged version, ABI, signing identity, release
flags, Firebase configuration, fixture exclusion and APK alignment. No signing
key was generated or replaced.

Windows uses the existing updater public key. The publish gate cryptographically
verifies the exact NSIS installer and the signature's bound version. The signed
installer is installed over the immutable public `.19` installer on an isolated
Windows runner; runtime versions, installation path and the actual application
WebView profile are checked. Its hash is retained in the workflow evidence.
This is an updater signature, not a commercial Windows publisher certificate.

Native identity and OS-vault continuity have a separate layered Windows CI check:
the actual NSIS upgrade preserves profile data, while paired debug runtimes built
from immutable `.19` and final sources use one disposable backend and OS vault
without pairing again. Published apps remain unpaired and isolated from production.
These checks do not claim a physical upgrade on the owner's computers or phone.
Android `.19 → 0.7.0` installation eligibility is verified through matching package,
certificate and increasing versionCode; a physical stable-APK upgrade is not
fabricated as a new owner test. The native store identifiers and persistence code
remain unchanged.

## Publisher, feed and focused validation

The publisher supports stable and `unstable.N` versions. Stable releases are not
prereleases; the operational release does not claim Latest. The official project
release is Latest. Versioned assets are never clobbered. Drafts are completed only
with identical existing bytes; retries of published identical releases are verified
no-ops. Conflicting assets or newer distributions fail closed.

`node-preview/latest.json` remains the compatibility endpoint for existing Android
and Windows apps. It advances only after the immutable distribution is verified,
uses exact versioned URLs and retains the Windows signature and Android versionCode.
Equal-version metadata cannot be silently replaced. Newer feed or distribution
versions block downgrade. Network failures remain errors in clients and publisher.

Local preparation passed client builds, 94 Node/shared JavaScript tests, 72 PWA/shared
tests, 38 release-tool tests, 77 portable Rust tests (two explicitly ignored), and
nine Android distribution-verifier tests. Release tests cover both channels,
tag/package/manifest mismatch, signatures, downgrade prevention, draft recovery,
immutable retries and network failure. Rust tests explicitly cover `.19 → stable`
and an installed stable client being current.

Final focused [Node CI](https://github.com/phcastello/Aegis/actions/workflows/aegis-node-ci.yml)
runs Windows native/upgrade checks, Android ARM64 distribution checks and browser UI
checks; the signed [release workflow](https://github.com/phcastello/Aegis/actions/workflows/aegis-node-release.yml)
builds and verifies both final installers on the integration commit. Exact results
and run URLs belong to the publication snapshot linked above. Earlier extensive
geofencing, recurrence, recovery and efficiency evidence is reused where sources
are unchanged; see the [completion record](v0.7.0-completion.md).

## Security correction and production

Release preparation identified a reachable Markdown reference-parser denial of
service in `markdown-it 14.3.2`. Both client manifests now pin `14.3.3`, the
[maintainer's patched release](https://github.com/markdown-it/markdown-it/security/advisories/GHSA-gfr2-rv44-r23c).
A bounded child-process regression exercises pathological unclosed references
with the chat renderer's options. Shared-client production dependency audit reports
zero advisories after this patch. This finding concerns renderer availability;
no credential leak or data compromise was established. Existing development/build
dependency advisories were assessed separately; this is not a repository-wide audit.

The public PWA contained the affected parser and therefore required a PWA-only
rebuild. Its previous image/assets and a custom-format PostgreSQL dump were backed
up privately; archive hashes and `pg_restore --list` plus a complete read to
`/dev/null` were verified before replacement. Only `aegis-pwa` was recreated using
the existing Compose project/configuration. Rollback retains the previous tagged
image and image archive; restoring that image requires only a PWA container replacement.

The API was already compatible and was not redeployed. All 26 expected migrations
were already applied, through `20261019120000_HybridMonitoringEnvelope`. No migrations,
database writes, volume replacement or data-container restart were required by this
release. Public API/PWA, native CORS and database readiness checks are recorded in
the final publication snapshot. Existing API images lack an embedded Git revision;
their image digest and observed contracts are recorded instead of inventing a SHA.

## Owner acceptance and remaining limits

The owner approved the specific `.19` Android route with battery saver enabled:
college departure, two departure notices about a block later, no premature home
arrival near the door, then two arrival notices after actual entry. This evidence
belongs to `.19` and does not establish universal latency, manufacturer behavior,
long-term battery life or every cancellation/offline-action scenario.

The Windows microphone report has no verified fix or new physical reproduction;
encoded silent audio can still reach STT. The possible classification of temporary
intentions as durable memory is deferred for future architectural review. Neither
issue is represented as repaired. Further physical acceptance remains distinct from
automated distribution, update and identity evidence.
