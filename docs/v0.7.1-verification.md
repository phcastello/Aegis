# Aegis v0.7.1 — verification record

This patch restores **It's Not Stalking. It's a Feature.** in the application
sidebar and About. Its secondary phrase is **You're terrible at hiding.** The
release preserves the v0.7.0 architecture and published evidence.

## Preparation and preserved state

The preparation audit observed `main`, `v0.7.0` and `node-v0.7.0` resolving to
`496a53032b5e33355374380f66f3736e65aa9ba6`. Neither `v0.7.1` nor `node-v0.7.1`
existed at that point. The prior release asset IDs, sizes and GitHub digests were
saved privately for post-publication comparison; these metadata are distinct from
local cryptographic verification of downloaded bytes.

Work uses `fix/v0.7.1-release-codename` in a separate worktree. The original checkout's
uncommitted About changes and draft v0.7.0 notes remain outside this patch. The
v0.7.0 and preview notes, tags, installers, hashes and physical-test attribution
remain unchanged.

## Scope and sources

The omission was structural: `AegisIdentityCard.vue` rendered Aegis and a version,
but no codename element. The fix adds semantic text through the existing host
App → ChatView → ConversationSidebar → AegisIdentityCard chain and the two About
sections. A small shared metadata source associates the approved identity with
the 0.7 family, including patch releases, without extending it to another family.

The native runtime remains the installed-version authority; the PWA uses its
build version. Update-feed and backend versions do not replace that value.
Codename and secondary phrase stay out of SemVer, application identifiers, native
storage and signing configuration. The sidebar displays the codename, while About
may also display the secondary phrase once. Update checks remain in Updates.

Version synchronization uses `apps/aegis-node/scripts/version.mjs`. The target
version is `0.7.1`, Android `versionCode 7001999`, above v0.7.0's `7000999`.
The existing signed distribution flow is reused; there is no signing-key rotation.

## Focused validation and publication evidence

The final publication evidence must distinguish host-level mounted UI checks,
browser screenshots with simulated native IPC, native Windows/WebView2 or Android
smokes, signed distribution gates, and physical owner-device tests. A passing
browser preview is not a physical native installation.

The focused regression covers the actual App-to-identity chain in both hosts,
sidebar and About content, numeric version formatting, family selection and
missing-metadata behavior. Layout checks cover open/collapsed state, new/existing
conversations, the accessible collapse control, mobile widths 320/360/412 CSS px,
desktop normal/minimum widths and 100%/200% text or zoom settings. Capture review
must inspect readable codename text, non-overlap and functional controls.

Final test outcomes, screenshots, merged commit, resolved tags, exact workflow
runs, installer hashes, signature checks and public updater URLs are recorded in
the publication snapshot attached to the
[official release](https://github.com/phcastello/Aegis/releases/tag/v0.7.1).
The [native release](https://github.com/phcastello/Aegis/releases/tag/node-v0.7.1)
hosts the immutable installers, signature, manifest and checksums. Until the gates
and public downloads are verified, this source record does not assert their success.

The upgrade check is specifically v0.7.0 → v0.7.1. Record certificate/versionCode
eligibility separately from actual installation, and profile/identity continuity
separately from physical acceptance. Reuse unchanged geofencing, reminder,
synchronization and persistence evidence from the
[v0.7.0 verification](v0.7.0-release-verification.md); this patch does not repeat
physical trajectories or present old measurements as v0.7.1 tests.

## Production baseline and rollback

Before deployment, public PWA and API health returned HTTP 200; the API responded
`{"status":"ok"}`. PostgreSQL accepted connections. All 26 expected migrations
were already applied, through `20261019120000_HybridMonitoringEnvelope`, with none
pending. No backend or migration change is required by this UI patch.

The live PWA image was
`sha256:b3450d664e74379e47ae78fd037e8b8f04b1f45f9be49a83d5fa2db02599fe01`.
A private Docker image archive and static HTML archive were saved and read back;
the saved index and JavaScript matched the publicly served bytes. Rollback tag
`aegis-aegis-pwa:pre-v0.7.1` preserves that image. The image archive SHA-256 is
`defd2fc8bb0cb5ba6e7d52a89fab999bb5f5b18d2329244e77fb6eae9e1de4c1`;
the static archive SHA-256 is
`ee2d78826ba7ac8ac28ea9180eca7efdfe15c9b1ef1557907b066ccb4139e234`.
These are rollback archives, not release installer hashes.

The existing Compose project is `aegis`, using its existing configuration and
environment. A PWA-only deployment can replace `aegis-pwa` with `--no-deps` and
preserve the API and data containers, mounts and start times. Rollback restores
the saved PWA image and recreates only that service. No database backup, migration,
volume replacement or API/data-service restart is necessary for replacing static
frontend assets. The publication snapshot records the actual deployment outcome,
public asset checks and unchanged API/data-container identities.
