## API, CORS and permissions

Official API default is defined once in Rust `build.rs`: `https://aegis.phcastello.com`. Shell or ignored `.env.local` variable `AEGIS_NODE_API_BASE_URL` overrides it at build time; `runtime_info` supplies the validated origin to Vue. Release requires HTTPS. Android loopback is rejected clearly. Retry does not change servers.

Browser transport uses `https://tauri.localhost` in bundled WebViews. Backend CORS explicitly adds this origin and local Vite port 1420, with optional semicolon-separated `AEGIS_CORS_ORIGINS`. No AllowAnyOrigin. Cross-origin TTS exposes the existing audio format/sample-rate/channel headers. An isolated real API container verified native-origin health, JSON preflight and exposed headers, and rejected an untrusted origin.

**Deployment required:** the currently running public backend still omits CORS for `https://tauri.localhost`. Deploy the updated backend before expecting native chat/streaming/audio against production. The owner's running API was not restarted. Rust diagnostic health bypasses browser CORS; Connected alone cannot prove parity.

Windows debug can use `http://localhost:8090`. Android must reach the backend and CLI Vite server over its network. Add the actual Vite origin explicitly through `AEGIS_CORS_ORIGINS`; do not commit machine IPs. Microphone capture needs a secure context: HTTP LAN Vite is insufficient; use trusted HTTPS development or a bundled HTTPS debug WebView. Bundled HTTPS WebViews can block HTTP API fetch as mixed content. Use reachable trusted HTTPS rather than disabling TLS/WebView security.

Capabilities apply only to local main/platforms: diagnostic IPC, scoped HTTP(S)/mailto opener, Windows updater check/download/install/restart, Android fixed feed-check command. No filesystem, shell, generic native HTTP, remote IPC, camera, location or notifications. Navigation stays on local assets/configured debug origin; new WebView windows are denied. External links use the system browser.

WebView microphone/autoplay use platform permission handling; other permission kinds are denied. Android adds RECORD_AUDIO/MODIFY_AUDIO_SETTINGS alongside INTERNET and AndroidX's internal receiver permission. Wry's existing bridge requests microphone access; no custom capture plugin. MainActivity handles system bars/cutouts/IME insets. Physical prompts/keyboard/orientation/lifecycle remain unverified for Stage 02. Production CSP limits fetch to the configured backend/IPC, with blob worklets for existing audio. OAuth secrets stay backend-only.

## Updater limitation and selected behavior

Identified/documented before client expansion: [official Tauri updater](https://v2.tauri.app/plugin/updater/) supports desktop; [platform metadata](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/updater/Cargo.toml) marks Android unsupported. This is a plugin platform limitation; the requested official mobile self-install cannot be claimed. It does not prevent stable signed APK distribution/shared Vue parity.

Windows checks once per app session; no update/network failure stays invisible. Newer version offers a non-modal “Atualizar”/“Agora não”. Explicit click downloads with progress, verifies signature/signed version, runs NSIS passive installer and requests restart through official process plugin. Downgrade is disabled. A JS guard accepts only the exact versioned HTTPS installer URL from this repository. Installation between published versions remains **NOT EXECUTED**.

Android checks the same HTTPS feed through a bounded native service; requires greater SemVer/code and the exact repository APK URL. “Baixar APK” opens that file in the system browser; Android performs user-confirmed installation and enforces package/certificate compatibility. No native progress/silent install/unknown-sources bypass/REQUEST_INSTALL_PACKAGES. APK protection is its stable Android signature, not desktop `.sig`. Metadata is HTTPS GitHub content, not a separately signed document. This avoids manually finding files but still needs physical A→B acceptance. Alternatives: future official mobile updater or store-managed updates; a bespoke privileged APK installer was not added to mask unsupported plugin behavior.

Feed: `https://github.com/phcastello/Aegis/releases/download/node-preview/latest.json`. Windows uses official `platforms.windows-x86_64` URL/signature; Android uses top-level `android.aarch64` URL/versionCode, outside `platforms` because the official desktop parser requires signatures for every platform entry. Actual Windows Rust tests deserialize this extension with the official updater parser. Metadata generation validates the signature's version comment. A real fixture signed with the official signer and `--app-version` passed; this proves signing preparation, not update installation.
