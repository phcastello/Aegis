## Reproducible builds and release

CI: `.github/workflows/aegis-node-ci.yml`, Windows 2022 x86_64 and Ubuntu 24.04 ARM64 Android. Web/backend regression is separate.
Release: `.github/workflows/aegis-node-release.yml`; push an immutable `node-v<VERSION>` tag or dispatch with an existing tag. Both builds must succeed before publishing.
Version source: `apps/aegis-node/package.json`. After changing it, run `npm run version:sync`; `npm run version:check` fails drift in Cargo/config/locks. Supported versions: X.Y.Z or X.Y.Z-stage.N, N=1..998. Android versionCode = major × 100000000 + minor × 1000000 + patch × 1000 + stage; stable reserves 999. Bounds major ≤20, minor ≤99, patch ≤999. This is monotonic through stages, stable versions, and subsequent patches.

Release files:
- `Aegis-Windows-x86_64-Setup.exe` (recommended NSIS installer)
- `Aegis-Windows-x86_64-Setup.exe.sig` (mandatory Tauri signature)
- `Aegis-Android-arm64.apk` (release signed APK, package com.aegis.node)
- `latest.json` (metadata with immutable version asset URLs)

All versioned releases are prereleases during development. A separate `node-preview` prerelease contains only the current `latest.json` feed at https://github.com/phcastello/Aegis/releases/download/node-preview/latest.json. The publisher refuses to overwrite a versioned release or downgrade the feed. Stable backend releases remain separate.

### Signing secrets

GitHub repository Settings → Secrets and variables → Actions needs:
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `TAURI_SIGNING_PRIVATE_KEY`, and optional `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (empty for the generated key).
Missing required values fail explicitly by secret name; no key value is printed.

Private signing material was generated on the implementation host in `~/.local/share/aegis/release-keys` (directory 0700, files 0600), outside Git. Android: PKCS12 RSA4096, alias aegis-release, 10000-day validity. The updater public key alone is committed in Tauri configuration. The helper reads the private files and supplies values to gh through stdin:

```sh
gh auth login
python3 apps/aegis-node/scripts/upload-signing-secrets.py
```

Requires GitHub CLI and authenticated access with repository secrets write permission. The implementation environment has Git SSH access but no GitHub CLI/token capable of writing secrets. No secrets were uploaded automatically.

**Back up both private signing identities and Android passwords securely before distributing installs. Losing the updater private key prevents signed updates to existing installations. Losing the Android key prevents updating existing APK installs under the same package. Do not regenerate keys for subsequent releases.** GitHub Secrets are not a backup: their values cannot be retrieved later.

Stage 01 debug APKs use a different signing certificate. Uninstall that development APK once before installing the first release-signed APK; local app preferences are lost, backend conversations remain. Subsequent releases must keep the release certificate and increase versionCode.

### Updater limitation and selected Android flow

The [official updater plugin](https://github.com/tauri-apps/plugins-workspace/tree/v2/plugins/updater) supports desktop, with Android explicitly unsupported in its [Cargo platform metadata](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/updater/Cargo.toml). Therefore Android self-install through this plugin is not claimed.
Windows uses the official signed updater, HTTPS metadata, `requireSignedVersion=true`, and default downgrade rejection. Android will check the same metadata and offer the exact immutable APK URL through the system browser, followed by Android's normal installation confirmation. Android's package manager verifies the existing certificate/package/version; the app never executes an unverified downloaded binary. This does not offer native download progress or automatic installation. A future official mobile updater or managed store distribution could replace this flow.
